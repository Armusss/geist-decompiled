# File boundary scan

`tools/boundary_scan.py` finds game units that hold more than one source file. CodeWarrior merges identical
literals within one translation unit, so if one unit's code reads the same constant bytes (0.0f, the
int-to-float double 0x4330000080000000, ...) from two different .sdata2 addresses, the unit contains at
least two files. The functions reading the first copy come before those reading the second, which gives a
range in which each file boundary must lie. Each piece's match count is listed; a piece where every function
already matches can usually be split off and flipped to Matching straight away.

How to split: move the piece's functions into a new src/game/u_<start>.cpp, give the new unit its .text range
and the data its asm references (.rodata/.data/.sdata/.sbss/.sdata2), define the globals it owns with their
retail initialisers, use symbols.txt names for its callees, then run tools/matching/audit.sh.
